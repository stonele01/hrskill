# 可视化报告与人机共同评审

## 报告形式

生成单候选人离线 HTML 报告，使用宿主已有 HTML/图表能力；简单 CSS 条形图和表格即可，不必建设系统。报告不依赖 CDN，不嵌入原始录音，不上传到公网。用户内容做 HTML 转义；不把简历中的 HTML 或脚本当代码执行。

同时保存 JSON 或 CSV 评分明细供复核。若当前宿主只能输出文字，提供等价报告并明确“HTML 未生成”，不能把聊天中的表格叫成已交付 HTML。完成后通过可用浏览器或渲染器检查桌面和窄屏：无截断，缺失值、证据和人工状态能读清；没有预览能力则说明未做视觉检查。

## 页面顺序

1. **摘要**：岗位、候选人编号、规则版本、报告日期、材料范围、暂定/待人工评审/已人工复核状态。明确显示“AI 建议”与“人工决定”。
2. **公司要招什么人**：岗位使命、近期成果、核心任务、必备条件、可培养项；每项来自哪次 HR/主管回答。
3. **分数与覆盖**：简历分、AI 面试分、人工评分独立卡片；每张卡片紧邻本阶段证据覆盖率。录音处理覆盖另列，不混成一个‘置信度’。
4. **能力对比**：横向条形图并排显示 AI 与人工的逐维度评分、权重和量表上限；未知显示灰色“未评估”，不能画成 0。不同量表或规则版本不可直接并排当成同尺度。
5. **证据详情**：能力项可展开到简历页码/段落或面试时间戳，含短原文、说话人、支持与反向证据、评分锚点和理由。文本链接只使用实际可用的材料定位。
6. **分歧与缺口**：AI 与人工分歧的维度、各自依据、未问到的问题、音频缺失或转写疑点、下一步核验方式。
7. **综合评审**：人工作出的决定、评审人、日期、理由、采纳/不采纳 AI 建议的原因、下一步安排。未收到这些信息时明确待填写。

多候选人报告仅在同岗位、同一规则版本和可比较阶段下汇总；把覆盖不足与完整材料分开说明，不用总分一键淘汰。

## 数据最小结构

以下为字段约定，不是虚构候选人数据；未知值用 null 或明确状态保存。

- `candidate_id`, `role`, `rubric_version`, `rubric_confirmed`, `report_status`
- `role_needs`：岗位目标、来源、HR 原话和确认后的可观察标准。
- `materials`：来源文件、类型、处理状态；音频另含总时长、处理区间、未知/失败区间、是否核听、工具记录。
- `criteria`：维度 ID、名字、权重、量表、行为锚点、验证方式。
- `assessments`：阶段（resume / ai_interview / human）、维度 ID、可空分数、评估人或模型、规则版本、证据 ID、理由、日期。
- `evidence`：ID、来源、时间/段落、说话人、原文、证据类型、识别疑点。
- `must_haves`：条件、状态、证据、待核实问题。
- `ai_recommendation`, `disagreements`, `follow_up_questions`
- `human_decision`：决定、评审人、时间、理由、引用证据；无人提供时为空。

报告里的总分从评分明细重算；无分数不能渲染为 0。保留版本，追溯修改；更改图表不会自动修改源文件。

## 人工复核怎么做

1. 面试官先按相同能力定义独立记录分数、观察和证据。如果已经看到 AI 分数，如实记录这一点，不伪称盲评。
2. 展示 AI 和各面试官的原始意见。多人评价逐人保留，未经约定不偷偷平均。
3. 逐项讨论分歧：证据遗漏、转写错误、量表理解不同，还是对岗位标准意见不一致？指出哪段材料能验证。
4. 如需改岗位标准，说明业务原因、更新版本，并对同批候选人一致重新评估。如只是纠正转写，记录修正位置及受影响评分。
5. 由指定的人给出最终阶段决定与理由。Agent 根据明确反馈整理记录；没有反馈时交付“AI 报告＋待人工评审区”，不代填同意录用、淘汰或主管签字。

“综合判定”默认是基于证据的人工复核结论。不要自定 AI 50%＋人工 50% 等权重。用户明确要求合成数字时，记录确认的比例、量表归一化、缺失值处理和适用阶段，同时保留全部原始分数；合成分不能绕过必要条件或人工决定。
