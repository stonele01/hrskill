# 根据需求和简历生成面试题

## 输入和一致性

读取已确认的用人需求卡、规则版本、简历和筛选证据。核心岗位能力及评分标准对同一岗位的候选人保持一致；针对简历的追问可以不同，但评估的是同一能力。沿用已有面试阶段和时长；未知时提供建议方案并标注待定。

先选择本轮确实能考察的能力，按时长安排核心题与备用追问，不输出一场面试无法问完的大题库。由不同面试官负责的维度注明分工。

## 三类题

1. **核心行为题**：询问与岗位相关的过去事件。所有候选人使用可比较的主问题和评分锚点。
2. **简历追问**：从具体项目、业绩、职责、未提供信息或前后矛盾出发；带原文引用。不能把追问写成已认定的指控。
3. **情境/工作样本题**：使用公司实际或明确标注为模拟的工作问题，观察分析和执行方案。适用于过往经历不完全对口、但可能具备可迁移能力的候选人。工作样本应简短、有相同条件，不要求免费交付公司正式业务成果。

问题逐项包含：题号、能力 ID、主问题、为什么问（需求＋简历依据）、追问、需要听到的证据、0–3 分行为锚点、预计时长。面试官记录表增加回答摘要、证据位置、分数、未知项。

## 追问要验证什么

- 情境与目标：当时的问题、规模、限制和衡量口径是什么？
- 个人行动：你本人负责哪部分、做了什么决定？同事或上级做了什么？
- 判断依据：比较过哪些方案，为什么选择这个方案？
- 结果与核验：基线、结果、时间窗口是什么？有哪些可描述的材料支持？
- 反思与迁移：什么没有奏效？换成我们公司的资源和约束会怎样调整？

不要把 STAR 等组织答案的方法当真实性检测，也不能因表达不流畅就判定经验造假。先问开放题，再澄清具体细节；不要在问题中泄露期望答案。

## 面试评分量表

优先沿用公司已经确认的面试量表，保留原量表，不悄悄转换。没有量表时提出下面的 0–3 分草案，用人方确认后使用；这是本地适配，和部分上游的 1–4 或 1–5 量表不同。

| 分数 | 原则 |
|---|---|
| 3 | 在岗位要求的复杂度、独立程度和约束下，回答提供了充分的具体行为证据 |
| 2 | 展示了部分所需行为，但范围、独立程度或关键步骤仍有缺口 |
| 1 | 有限证据表明只覆盖少数关键动作，需要明显支持 |
| 0 | 可归属于候选人的有效回答显示未达到已确认要求；需说明具体反向证据 |
| 空白 | 未问到、未作答、转写不清、说话人不明或材料无法判断 |

每个维度还必须写岗位专属锚点；只写“差/一般/好”不能用于评分。未知不能当作 0。若候选人没有相关经历，可通过同标准的情境题补证，不能凭年限或表达包装打分。

## 示例：异常诊断与处置（模拟岗位）

主问题：“讲一次你发现投放消耗增加、订单却没有同步增长的情况，你怎么判断并处理？”

简历追问：“简历写到 ROI 从 1.5 提升到 2.3。当时的口径、周期和预算有没有变化？你个人负责哪些动作？”

锚点草案：3=核对口径并定位链路问题，解释方案取舍、验证结果及权限边界；2=能定位部分原因并调整，但验证或对照不完整；1=只能描述局部执行动作，难以说明诊断依据；0=在澄清问题后仍明确主张忽略已确认的预算或核算约束，且无法提出符合岗位要求的处理方案。最终锚点由用人方结合岗位实际确认。
